# 全員一致ゲーム 再接続ループ疑いの検証

日次ログレポートの所感が 25 日中 19 日「再接続ループの可能性がある」と書いていたので、
ログとコードの両方から根拠を確認した。結論は **名指しされた部屋は正常、ただし別の部屋で本物のループが1件あった**。

関連: auto/bot/logs/unanimous-game/2026-08-23（最初に名指しされた部屋 2196）、auto/bot/logs/unanimous-game/2026-09-13（本物のループ 5242）

## 追記 2026-10-13: 参加 0 で短命接続が多い部屋は「URL 直開きの行き止まり」

10/12 の日次ログで room 4866 が「短命接続が半数超え（32 接続・59%・参加 0）」として ⚠️ になった。
close code が取れるようになったので中身を見た。

- 6 分間ずっと `userCount = 1`（GM だけ）なのに、同時接続は最大 5
- 切断は 1001（ページを離れた）が中心で 1006 が混じる。自分で閉じる 1000 "leave" はほぼ無い
- `player_joined` は 0

非メンバーが WebSocket をつなぐ経路は `/room/:id` を直接開くことだけ（入室画面経由なら先に `/join` する）。
そして部屋画面には参加ボタンが無かった。つまり **URL を受け取った人が部屋を開き、入れずに閉じたり読み直したりしていた**。
再マウントのループ（1000 "leave" が並ぶはず）でも回線（1006 が大半になるはず）でもない。

直近 7 日で「在室 1・参加 0・同時接続 4〜6」の部屋は 4866 を含めて 6 件（2996, 9549, 4866, 7129, 8332, 4325）。
10/09 の 9049 も、GM 1 人に対して 1 接続が 0.5〜2 秒で 1001 切断 → 再接続を数分繰り返す形で、同じ行き止まりと読める。

**対応**: 部屋画面で userId を持たず GM でもない人に、待機中なら「このルームに参加」ボタンを出す。
ゲーム中・終了後は「次のゲームから参加できます」と案内する（ラウンド途中で人数が増えると判定が崩れるため）。
名前・アイコンの生成は入室画面と共通の `src/client/app/lib/player.ts` に移した。

**次に見るもの**: デプロイ後、短命接続の表に参加 0 の部屋が載らなくなるか。載り続けるなら別の原因を疑う。

## コードが示す理由

`RoomDurable.ts` と `room.tsx` を読むと、接続回数が長い部屋ほど増えるのは設計どおり。

1. スマホがバックグラウンドに行くと WebSocket が切れ、サーバの `webSocketClose` → `removeUserById` で `player_left`
2. 復帰すると `visibilitychange` で WebSocket を張り直し（`ws_connected`）
3. `state` を受け取った `ensureMembership` が自分が居ないことに気づき、HTTP `/join` で入り直す（`player_joined`、**新しい userId**）

つまり背景復帰 1 回につき「切断・退出・接続・参加」が 1 セット増える。
長い部屋 × 人数 × スマホ利用の回数がそのまま接続回数になる。

クライアントの再接続自体は既に絞られている:
指数バックオフ（1s → 30s）、最大 6 回、非表示中は再接続しない、サーバが意図的に閉じた場合は再接続しない。

## レポート側の何が悪かったか

- 表の題名が「WS 接続回数が多い部屋 TOP5（**再接続ループ検出**）」で、所感に結論を先に渡していた
- 「長時間居座り TOP5」と「接続回数 TOP5」は構造的に同じ部屋が上位に来る。プロンプトの
  「同じ ID が複数の表で上位 → 異常」という例に毎日一致していた
- 参加者数の KPI も背景復帰の回数ぶん水増しされていた

## 本物のループ

「接続の半数以上が 10 秒未満で切れた部屋」で絞り直すと、30 日で 19 部屋（≈0.6 件/日）。

**room 5242（2026-09-13 JST）**
- 16:33Z 作成 → **16:35Z からの 5 分間に 116 回接続**（2〜3 秒に 1 回）
- 接続 131 = 参加 131 = 切断 131、退出 130。10 秒未満が 109（83%）
- 平均在室 2.7 人。16:46Z に収まり、4 ラウンド遊んで 16:50Z に閉室
- 2 分後に room 4215 がほぼ同じ人数で作られ、最初の 5 分だけ 38 回接続 → 部屋を作り直した可能性

接続・参加・切断が完全に揃っているので「接続 → 参加 → 数秒で閉じる → 再接続」の繰り返し。
現状のログには close code が無く、**クライアントが自分で閉じている（1000 "leave"）のか、切られている（1006）のか**が
判別できない。`room.tsx` の effect cleanup が `leaveRoom` を呼ぶので、何かの理由で
コンポーネントが再マウントを繰り返すとこの形になる（`onopen` で `retry = 0` に戻るため回数に上限がない）。

## 変更したこと

**unanimous-game（ログ）** — 部屋の挙動は変えない
- 背景復帰の入り直しは `player_rejoined` として `player_joined` から分ける（クライアントが `/join` に `rejoin: true` を付ける）
- `ws_disconnected` の `value` に close code を入れる

**nasubi-bot（レポート）**
- 「接続回数 TOP5」を「短命接続（10 秒未満）が半数を超える部屋」に置き換え。接続 20 回以上・短命率 50% 以上で絞り、該当が無い日は表ごと出さない。該当があれば ⚠️ を notes に積む
- 長時間居座り TOP5 に接続・参加(+再参加) の列を追加
- 再参加（背景復帰）を KPI に分ける
- プロンプトの例を「表の並び順だけを根拠にしない」「回数系の絶対値は異常のサインではない」に変更。背景復帰の挙動は `summary_hint` で事実として渡す
